# 安全设计

> 保密边界不能靠提示词解决（设计第七章）。以下每一条都由执行层代码实施，而不是写在提示词里。

## 一、环境路线与材料准入

| 路线（`[environment] route`） | 可处理的材料 | 说明 |
|---|---|---|
| `public_dev` 公开材料研发版（默认） | 公开且获准用途的材料、合成测试任务 | 检测或申报为内部、敏感、工作秘密的材料一律禁止进入 |
| `unit_approved` 单位批准的业务环境 | 经明确审查准入的材料 | 须同时开启 `accept_internal_materials = true`（按单位制度）；模型只接收不高于其 `max_clearance` 的材料 |
| （涉密） | 不在本系统能力承诺范围内 | 不提供该选项；带密级标志的材料在任何路线都禁止进入 |

准入扫描（`parsing/admission.py`）**先于任何模型处理**，覆盖正文、文件名、批注、修订痕迹、隐藏文字、隐藏工作表与行列、页眉页脚、脚注、文档属性：

| 发现 | 判定 |
|---|---|
| 密级标志（绝密、机密、秘密★…） | 禁止进入，原件立即删除 |
| 工作秘密、内部、敏感标注 | 公开研发版禁止；单位环境按配置 |
| 身份证号（校验位）、批量手机号、银行卡号（Luhn）、批量邮箱 | 公开研发版禁止；单位环境须人工确认 |
| 隐藏内容、提及涉密、文件名含密级字样、疑似提示注入 | 须人工确认 |
| 未申报属性 | 先暂停，须人工确认（不允许“先上传模型再判断是否敏感”） |
| 多份材料聚合 | 聚合风险提示，人工判断 |

“材料准入确认”节点永远不能被无头模式自动接受；模型通道添加的材料不能申报属性。

## 二、出网网关（唯一出口）

`harness/egress.py`：

- 默认拒绝；`[egress] allowed_hosts` 白名单之外的主机一律拒绝（本机回环地址除外；局域网 `*.local` 主机不是本机，须列入白名单）；
- 模型适配不跟随重定向（否则材料可能被转发到未核准的主机）；本机模型不经环境变量中的代理；
- 涉密路线拒绝一切出网；属性未知的材料不出网；
- 公开研发版只允许公开材料出网；每个模型的 `max_clearance` 限制可发送的材料属性（公共云模型应保持“公开”）；
- 每次判定都写审计日志（主机、目的、材料属性、内容哈希）；
- `gongwen model test`（连通测试）与 `gongwen model remote`（查询可用型号）同样经过网关，未获准的主机在发出请求之前即被拒绝；`gongwen model add` 只有显式加 `--allow-egress` 才把服务主机加入白名单，否则只打印应加入的那一行。

模型密钥只从环境变量读取：配置文件只记录变量名（`api_key_env`），`gongwen model add` 拒绝把疑似密钥本身当作变量名写入；`gongwen model list`、`gongwen doctor` 只显示变量是否已设置；接口错误信息中回显的密钥一律打码；审计日志不记录请求头。

模型调用、MCP 返回内容都受此约束：MCP 客户端会把工具结果送入其自身模型，本系统无法控制其去向，因此只返回不高于 `[mcp] max_clearance`（默认“公开”）的任务内容。

## 三、权限：人—事项—材料—工具动作

`harness/permissions.py`：

- 人工角色：经办人（drafter）、审核人（reviewer）、签批人（approver）、管理员（admin）；
- 模型通道：planner、parser、retriever、ledger、outliner、drafter、reviewer、reviser、layout、packager、agent、mcp，各自只有完成本职所需的动作；
- **只能由人执行**：处理审核节点、导入审批记录、确认材料准入、登记依据；
- **任何主体都不被授予**：外发、发布、电子签章、用印（`NEVER_AUTOMATIC`）；
- 起草通道不能写入审批结果；审校通道不能修改正文；检索通道只能检索获授权材料；
- 主体可限定可访问的事项范围与材料属性上限。

修改建议走“提议—人工采纳”：模型只能 `revision_propose`，采纳必须由人执行（`/apply`、`gongwen task apply`）。

## 四、工具管线

`harness/tools.py` 每次工具调用依次经过：参数校验（模型给出的参数是不可信输入）→ 阶段/白名单 → 仅限人工检查 → 权限引擎 → 审批策略（越出工作区等需人工审批，非交互环境一律拒绝）→ PreToolUse 钩子（退出码 2 阻断）→ 幂等检查 → 执行 → PostToolUse 钩子 → 审计。

## 五、提示注入

- 资料进入模型提示前一律包裹为带编号的 `<untrusted>` 数据块，系统提示声明其中的任何指令都不得执行；
- 确定性检测疑似注入语句（忽略指令、改变身份、套取提示或凭据、要求外发、要求执行命令、要求签发用印、伪造审批、要求写入审批结论等），准入阶段标记并须人工确认，审校阶段检查是否进入文稿；
- 即使模型被诱导，工具白名单、权限引擎与出网网关仍在执行层兜底。

## 六、审计最小化

- 会话日志为追加式 JSONL，每条包含上一条的哈希；`gongwen session verify` 校验链条完整性；
- 超过 400 字的字符串字段只记 SHA-256、长度与前缀；模型请求与响应只记模板编号、对象编号与内容哈希；
- 不保存材料全文副本与推理文本；推理模型返回的思考内容（`reasoning_content`、正文中的 `<think>` 标签）不作为答案、不写入日志；需要重建时由“日志 + 受控存储”重建。

## 七、本地审阅服务

`gongwen serve`：只绑定本机回环地址；写操作需要本次启动生成的会话令牌，并校验 Host 与 Origin（防跨站请求与 DNS 重绑定）；任务、事项编号做白名单校验（防路径穿越）；设置 CSP 与 `nosniff`。

## 八、宿主工具的边界

当 gongwen 作为 MCP 服务接入 Codex、Claude Code、grok、ZCode 等宿主时，**宿主智能体对工作区文件的直接读写不受 gongwen 控制**。建议：

1. 把 `[environment] data_dir` 放在宿主工作区之外，MCP 服务用 `-C` 指向该目录；
2. 不在宿主工具的自动执行模式下处理非公开材料；
3. 宿主工具的代码索引、云端摘要等功能不得覆盖办文数据目录；
4. 需要处理内部材料时，在本机终端（`gongwen task …`）或本地工作台中办理。

## 九、不做的事

不自动签发、不自动用印、不电子签章、不无人审核外发、不自动认定合法合规、不承诺涉密能力；成文日期、发文字号、签发人不由系统填写。
