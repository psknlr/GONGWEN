# 文种覆盖

系统按《党政机关公文处理工作条例》（中办发〔2012〕14号，下称“条例”）第八条的 15 个法定文种起草和检查公文，并覆盖通知、函、意见等文种的常见变体，以及由法定文种印发或作为内部材料使用的主要事务文书。

每个文种都有三件事是固定的：

- **结构**：正文分几部分、各部分写什么（`src/gongwen/skills/outline_planning.py` 的 `GENRE_SECTIONS`、`VARIANT_SECTIONS`）；
- **内容来源**：每部分只用材料中的事实、措施和真实决定；材料没有的，留【待补】并在提纲确认节点提示；
- **不代填**：发文字号、成文日期、签发人、印章、审批结论，以及批复的答复意见、通报的表彰批评决定、决定事项、纪要的议定事项、决议事项、任免事项等须由真实决定支撑的内容，系统一律不代为决定。

每个文种至少有一个回归用例（见 [`evaluation.md`](evaluation.md)），表中列出用例编号。

## 一、法定文种（条例第八条）

| 文种 | 行文方向 | 格式 | 正文结构 | 只取真实材料、不代为决定的内容 | 权限与程序检查 | 用例 |
|---|---|---|---|---|---|---|
| 决议 | 会议文书、公布性 | 通用；无主送、无落款、无版记 | 题注“（××年×月×日××会议通过）”→ 审议情况 → 决议事项 → 要求 | 通过日期和会议名称、决议事项（须为会议通过的内容） | GW-GENRE-015 决议须为会议讨论通过的事项 | GR-32、FL-24 |
| 决定 | 下行 | 通用 | 依据 → 决定事项 → 要求；依据在前时不另加“现作出如下决定” | 决定事项（须来自研究决定，评审结果只作依据） | 程序：涉及权利义务时提示合法性审核 | GR-25、GR-53 |
| 命令（令） | 下行、公布性 | 命令格式：发文机关标志“××令”、令号，不设标题，签发人签名章，无版记 | 公布语：“《××》已经××会议通过，现予公布，自××起施行。” | 所公布的名称、审议会议、施行日期 | GW-GENRE-013：人民政府、国务院及其部门（部门令）可发令；地方政府部门、企事业单位不得发令，提示改用通知、通告 | GR-33、GR-34、FL-21、FL-23 |
| 公报 | 公布性 | 通用；标题不加“关于”，题注写发布机关与日期；无主送、落款、版记 | 照材料陈述主要情况与数据 | 数据（逐项可回溯到材料） | — | GR-35 |
| 公告 | 公布性 | 通用；无主送 | “现将有关事项公告如下。”→ 事项 →“特此公告。” | 公告事项 | — | GR-50 |
| 通告 | 公布性 | 通用；无主送 | “现将有关事项通告如下。”→ 应遵守或周知事项 →“特此通告。” | 周知事项 | — | GR-24 |
| 意见 | 上行、下行、平行 | 通用 | 背景 → 意见（同一部分两条以上分（一）（二））→ 要求；结束语按行文方向 | 措施照材料原句，不增设指标 | 上行意见的结束语“以上意见，如无不妥，请批转……”；下行“请结合实际认真贯彻执行” | GR-42、GR-51 |
| 通知 | 下行、平行 | 通用 | 按变体，见第二节 | 任务、时限、报送要求取自材料 | 部门不得向下级政府发指令性通知（GW-ROUTE-007）；减负：新增高频报送、留痕要求 | GR-04、GR-16、GR-30 等 |
| 通报 | 下行 | 通用，不设层次标题 | 事实经过 → 表彰或批评决定 → 要求 | 表彰、批评决定；问题事实照写（含“尚未启动”等） | — | GR-22、GR-23、GR-43 |
| 报告 | 上行 | 通用；附注联系人 | 工作开展情况 → 存在的问题 → 下步打算 | 进展与问题照材料；“尚未”“未完成”归入问题 | 报告不得夹带请示事项（GW-GENRE-003）；上行文签发人 | GR-03、GR-08、GR-26、GR-29、GR-56、FL-17 |
| 请示 | 上行 | 通用；附注联系人 | 背景 → 理由 → 请示事项 → 资源测算 | 申请金额取测算合计，资金来源不补写 | 一文一事（GW-GENRE-002，起草前即提示）；主送一个上级机关；不得主送领导个人；用户写“报告”而实质请求批准时改判为请示（GW-GENRE-012） | GR-01、GR-02、GR-09、GR-13、GR-17、SR-16 |
| 批复 | 下行 | 通用，不设层次标题 | 引来文标题与文号“收悉”→ 答复意见 → 要求 | 答复意见只取会议决定或审批意见，金额以决定为准 | — | GR-18、GR-19 |
| 议案 | 人民政府→同级人大或其常委会 | 通用；政府主要负责人签署 | 提请审议事由（起草情况、政府审议情况）→“现提请审议。” | 草案名称、政府审议会议 | GW-GENRE-014：只能由人民政府提请，主送同级人大或其常委会 | GR-36、GR-37、FL-22 |
| 函 | 平行 | 信函格式 | 按用途：商洽、询问（“函询”“请函复”）、告知（“函告”“特此函告”）、请求批准、复函（“××收悉”“特此函复”）、对征求意见稿的反馈 | 商洽、反馈事项取材料中的事实与建议；复函不把来函自身的请求写成本机关事实 | 同一地方的政府部门之间请求批准用函（GW-ROUTE-011）；称“贵局”，不用“你局”（GW-GENRE-006）与指令口吻（GW-GENRE-007） | GR-05、GR-06、GR-10、GR-20、GR-41、GR-58、GR-59、FL-13、FL-20 |
| 纪要 | 会议文书 | 纪要格式；出席、请假、列席名单 | 开头取会议记录的时间、地点、主持人 → 主要情况 → 议定事项 → 待研究事项 | 议定事项（建议、未决事项不写成议定） | — | GR-14、GR-31 |

## 二、常见变体

| 变体 | 识别方式 | 写法 | 用例 |
|---|---|---|---|
| 部署类通知 | 默认 | 主要任务 → 工作要求；材料中的全部任务都写入，已写明时限与报送要求时不另留“工作要求”待补 | GR-04、GR-30 |
| 印发类通知 | 需求为“印发××方案/要点/办法/细则/制度” | 标题“关于印发《××》的通知”；正文只写印发事项；方案、要点作附件，办法按“第×条”编排 | GR-21、GR-49 |
| 转发类通知 | 需求含“转发” | 标题“××转发××关于××的通知”；引来文标题与文号；来文附后；本机关要求单列，来文要求不写成本机关的话 | GR-38 |
| 批转类通知 | 需求含“批转” | 标题“××批转××关于××意见的通知”（省去“的意见的通知”） | GR-57 |
| 会议通知 | 需求为召开、举办会议或培训 | 会议时间、地点、参会人员、会议内容、有关要求分项；不补写议程 | GR-39 |
| 任免通知 | 需求含任职、免职、任命、聘任 | 照录任免决定，不设层次标题；提示核对原始决定 | GR-40 |
| 知照性通知 | 需求为启用或停用印章、更名、成立或调整机构与组成人员、放假、迁址等 | 不设任务、要求层次，正文直接陈述告知事项 | GR-52 |
| 联合行文 | 需求含“与××联合印发”“会同××发文” | 标题并列各发文机关名称；主办机关署名在前；联合机关简称按主办机关地域补全；提示会签（GW-PROC-003） | GR-55 |
| 指导意见、实施意见、若干意见 | 需求含“指导意见”等 | 标题“关于××的指导意见”，不写成“××的指导的意见” | GR-51 |
| 答复上级询问的报告、报送情况的报告 | 需求含“答复……询问”“向××报送” | 事由去掉答复对象、报送对象 | GR-26、GR-56 |
| 复函、反馈意见函、询问函、告知函 | 需求含“复函”“回复意见”“询问”“告知” | 见第一节“函” | GR-20、GR-58、GR-41、GR-59 |
| 表彰、批评、情况通报 | 需求含“表彰”“批评”或进展情况 | 见第一节“通报” | GR-22、GR-23、GR-43 |

## 三、事务文书

方案、办法、细则、要点本身不是文种，作为正式公文下发时须由通知印发（第二节“印发类通知”）；总结、汇报材料、调研报告、讲话稿、简报可作为内部材料独立成文。用户明确要求事务文书时，系统按事务文书起草，不改判为报告等法定文种。

| 类型（别名） | 格式 | 正文结构 | 用例 |
|---|---|---|---|
| 工作方案（实施方案、工作计划、计划） | 通用 | 工作目标 → 工作范围 → 主要任务 → 职责分工 → 进度安排 → 保障措施 → 评价方式；多个时间节点归入进度安排；“工作计划”开头写“制定本计划” | GR-15、GR-54 |
| 工作要点（要点） | 通用 | 按（一）（二）列重点任务，照材料原句，不增设指标 | GR-48 |
| 管理办法（办法、实施细则、细则、管理制度） | 通用，一般作为印发类通知的附件 | 按“第×条”编排，条文照材料原句 | GR-49 |
| 工作总结（总结、年度总结） | 通用 | 主要工作 → 成效 → 问题 → 下步打算；工作与成效不重复同一事实 | GR-27 |
| 汇报材料（汇报、情况汇报） | 无版头、版记 | 标题“关于××的汇报”；概况 → 工作 → 问题 → 下步 | GR-46 |
| 调研报告（调研） | 无版头、版记 | 调研方法 → 主要发现 → 原因分析 → 对策建议 | GR-44 |
| 讲话稿（讲话、发言稿） | 无版头、版记、主送、落款 | 标题“在××上的讲话”，题注讲话人，称呼“同志们：” | GR-45 |
| 简报 | 简报报头、期号 | 标题去掉“一期”“工作简报”，正文照材料 | GR-47 |

## 四、格式类型

| 格式 | 适用 | 版头 | 落款 | 版记 |
|---|---|---|---|---|
| 通用（`general`） | 多数文种 | 发文机关标志“××文件”、发文字号；上行文标注签发人 | 署名、成文日期、印章 | 抄送、印发机关和印发日期 |
| 信函（`letter`） | 函 | 发文机关名称、双红线（GB/T 9704—2012 10.1） | 同通用 | 同通用 |
| 命令（`command`） | 命令（令） | “××令”、令号（10.2） | 签发人职务、签名章、成文日期（7.3.5.3） | 无 |
| 纪要（`jiyao`） | 纪要 | “××纪要”（10.3） | 不加盖印章（实务）；出席、请假、列席名单 | 同通用 |
| 简报（`brief`） | 简报 | 简报报头、期号 | 无 | 无 |
| 无版头（`plain`） | 汇报材料、调研报告、讲话稿 | 无 | 汇报材料、调研报告署名不盖章；讲话稿不署名 | 无 |

决议、公报只保留标题、题注与正文；公告、通告不设主送机关。

## 五、外部文稿检查

`gongwen check` 对任何文种的现成文稿都做相同的规范检查，并按文种补充：

- 识别通用版头（份号、密级、紧急程度、发文机关标志、发文字号、签发人）、命令格式（“××令”、令号，含“2026年第5号”）、简报期号，以及“职务　姓名”的签名章落款；
- 文种与发文主体：GW-GENRE-013（命令）、GW-GENRE-014（议案的提出机关与主送机关）、GW-GENRE-015（决议须写明通过的会议）；
- 文种与行文方向、结束语、称谓（GW-GENRE-001～012）、一文一事、请示报告混用、主送领导个人、上行文抄送下级等；
- 征求意见稿、草案、送审稿是讨论对象，不作为行文依据核验。

对应用例：FL-17～FL-24、GR-08～GR-13。

## 六、局限

- 信函格式：首页版头、上下两条红色双线、发文字号位置与首页不显示页码已按 10.1 排定并经渲染核验（LAY-LETTER-*）；但 10.1 要求“最后一个要素与下双线相距 3 号汉字高度的 7/8”，首页仍沿用通用版心，这一距离约 14mm，须定稿时调整；
- 版式核验在本环境以替代字体渲染（未安装方正小标宋、仿宋_GB2312 等），字库替代会如实标为警告，定稿须在安装指定字库的环境复核；
- 联合行文的署名按行排列；印章与署名的对应位置（GB/T 9704—2012 7.3.5.2）须定稿时目视核对；发文机关标志只用主办机关名称（7.2.4 允许）；
- 系统按条例和 GB/T 9704—2012 处理党政机关公文，不起草党内法规、规章正文和地方性法规正文，也不处理涉密公文（FL-11）；
- 管理办法等可能属于行政规范性文件，系统只提示合法性审核、公平竞争审查等程序，不判断是否已经通过；
- 规划、述职报告、倡议书、邀请函等未单独建模：规划可按工作方案起草，邀请函按函起草，其余须人工撰写；
- 文风、篇幅与领导意图的契合度须人工把握，评测只覆盖已知风险点（见 [`evaluation.md`](evaluation.md) 第五节）。
