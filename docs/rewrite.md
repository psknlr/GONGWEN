# 固定句标定与按提示词改写

文稿形成后，可以先“标定固定句”，再按一句改写要求（提示词）让模型重写其余句子。改写只产生**建议**，由人逐条采纳；采纳后作为修订形成新版本，并重新经过独立审校。

## 一、固定句从哪里来

每个正文句子都有锁定状态。来源有三种，优先级从高到低：

| 来源 | 说明 | 能否被覆盖 |
|---|---|---|
| 人工 | 在工作台点 🔒/🔓，或 `gongwen task locks --lock/--unlock` | 人工决定始终优先；`--reset` 恢复为系统标定 |
| 模型标定（可选） | 按改写要求，由模型指出“改写后容易走样”的句子，如任务分工与责任主体、法律法规或政策的规范表述、对方的请求事项、表彰批评与任免的表述、限定条件与例外 | 只能**增加**锁定，不能解除规则锁定，人工可随时解锁 |
| 规则标定（确定性） | 含数字、金额、日期等事实数据；引用文件标题或发文字号；审批、决定与会议议定事项；引用来文（“收悉”）；引用依据；惯用结束语；含【待补】占位 | 人工可解锁（解锁后的改写仍受下述校验约束） |

每个锁定都附理由，可在工作台“改写”页或 `gongwen task locks` 中查看。锁定只影响 AI 改写，不改变文稿内容，也不产生新版本。

## 二、改写的校验

模型只收到“可改写”的句子（固定句只作上下文）。每条返回的改写都经确定性校验：

| 结果 | 情形 |
|---|---|
| **已拒绝**（不能采纳） | 改写了固定句；改动或代填了【待补】；新增无来源数字（不在本事项事实账本中）；新增或改动时限（如“6月底”改为“9月底”）；新增文件标题或发文字号；新增“经××批准/同意”“研究决定”“经核实”等说法；含疑似指令性语句 |
| **需人工确认** | 义务强度变化（如“要”改为“可以”）、事实状态升级或降级、实施范围扩大、决策状态变化、删去条件与例外、删去数字或时限、删除整句 |
| **可采纳** | 以上都不涉及的措辞调整 |

采纳时：已拒绝的不能采纳；需人工确认的须明确勾选（命令行 `--include-flagged` 或 `--patches`）；生成建议后句子已被他人修改、或已被锁定的，建议视为过时并跳过。采纳的句子记为“模型（某某采纳）”，修订记录中保留原文与改写，便于追溯。

未配置可用模型时，系统如实说明 AI 标定与改写不可用，不产生任何建议，原稿不变；仍可逐句锁定与人工修改。

## 三、命令行

```bash
gongwen task locks <任务>                                 # 查看每句的锁定状态与理由
gongwen task locks <任务> --lock s-003 --reason 职责分工须保持原文
gongwen task locks <任务> --unlock s-005                  # 解锁（如允许改写某句结束语）
gongwen task locks <任务> --reset s-005                   # 恢复为系统标定
gongwen task locks <任务> --ai "语言更简洁，突出责任落实"   # 模型按改写要求补充标定（只增不减）

gongwen task rewrite <任务> -p "语言更简洁有力，突出责任落实" [--ai-calibrate] [--lock s-003]
gongwen task rewrite-apply <任务> RW-001                  # 采纳全部“可采纳”的建议
gongwen task rewrite-apply <任务> RW-001 --patches PA-002,PA-004 --include-flagged
gongwen task rewrite-discard <任务> RW-001
gongwen task rewrite <任务> -p "……" --apply safe         # 生成后直接采纳可采纳的建议
```

对话模式（`gongwen chat`）中用斜杠命令：`/locks`、`/locks lock s-003`、`/locks ai <改写要求>`、`/rewrite <改写要求> [--ai]`、`/rewrite-apply [建议编号…] [--all]`、`/rewrite-discard`、`/import 修改稿.docx [--apply]`。模型助手不能执行这些命令。

## 四、工作台

`gongwen serve` 打开任务页，右侧“改写”页：

- 填写改写要求，可勾选“改写前由 AI 标定固定句”，或单独点“AI 标定固定句”；
- 每条建议显示原文、改写、理由和校验结果；“可采纳”的默认勾选，“已拒绝”的不能勾选；点“采纳所选”形成新版本并重新审校，或“放弃本次改写”；
- 下方逐句列出锁定状态，点 🔒/🔓 切换，点“修改”可直接人工改写某句（作为人工修订提交）；
- 左侧正文中，固定句以虚下划线标出，悬停可见锁定理由。

离线的送审包工作台（`workbench.html`）只显示固定句与改写结果，不能操作。

## 五、回读 Word 修改稿

在 Word、WPS 中直接修改导出的 `.docx` 后，可以把修改带回任务，而不是脱离系统另存一份：

```bash
gongwen task import-edited <任务> 修改稿.docx            # 逐句比对：列出改动、删除的句子
gongwen task import-edited <任务> 修改稿.docx --apply    # 确认后作为人工修订提交，形成新版本并重新审校
```

工作台“改写”页也可上传修改稿（不超过 700KB），先显示比对结果，再点“提交为人工修订”。

- 比对按句子对齐；新增的句子并入相邻句（文稿结构由提纲确定，回读时不新增段落），整段删去的不留空行；
- 标题、层次标题、主送机关、表格与附件的改动不自动采用，只列出提示，须在任务中另行修改；
- 回读的修改按人工修订处理：修改中的事实状态升级、写入未批准事项、义务强度变化等，照常由独立审校指出；
- 也支持 `.txt`、`.md` 和带文字层的 `.pdf`。

## 六、边界

- 改写范围为正文句子；标题、主送、落款、附件说明等要素和附件正文不在改写范围内（附件正文可在其文稿中人工修改）。
- 校验能拦住新增事实、数字、时限、依据和审批说法，以及义务强度等语义变化，但不能判断文风是否更好、是否符合领导意图，采纳前须人工阅读每条建议。
- 模型通道（对话代理、MCP 客户端）不能锁定、改写或采纳，只能提交修改建议，由人处理。
