# 技能7 受约束起草

## 目的
让文字“像公文”不难，难的是不越过证据：不新增事实、不夸大成绩、不把拟议写成已完成、不把讨论写成决定、不擅自增加任务和预算。

## 起草规则
1. 先由确定性模板按段落计划生成每一句，并附证据引用（fact / policy / measure / material）；
2. 有模型且出网网关允许时，模型只改写表达，返回逐句 JSON（含 refs）；
3. 校验器逐句复核，以下任一情况即拒绝模型稿、回退模板稿并留痕：
   - 出现证据中没有的数字；
   - “拟/计划”被写成“已完成”，“材料记载”被写成“经核实”；
   - 义务强度变化（“可以”→“必须”）、条件或例外被删除；
   - 写入“经批准”“同意”等审批结论，或填写发文字号、成文日期；
   - 删除【待补】占位；
4. 自称按单位类型（我委 / 我院 / 我校）；开头只引用实体依据；结束语与文种、行文方向匹配（实务惯例）。

## 占位规则
资金来源、联系人等缺失信息写成【待补：……】；发文字号、成文日期、签发人写成【待…由办理流程确定】，排版时高亮。

## 如何查看与修改
- MCP：`draft_view`（带块号、句号）、`revision_propose`（提交修改建议，须人工采纳）；
- 命令行：`gongwen task draft <任务>`；人工修改用 `gongwen task revise`。
