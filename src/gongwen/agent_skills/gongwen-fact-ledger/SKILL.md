# 技能5 事实账本构建

## 目的
文稿中的每一个数字、每一项进展都要能回答：来自哪个文件哪个位置、原文怎么写、是什么口径和时点、谁核实过、是不是还只是“拟议”。

## 事实状态（不可升级）
| 状态 | 含义 | 文稿中的写法 |
|---|---|---|
| 已核实事实 | 经人工核实 | 可直接陈述 |
| 材料记载 | 材料中写明但未核实 | 可陈述，送审前列为待核 |
| 计算结果 | 由账本内数据按公式计算 | 附公式，可复核 |
| 拟议内容 | 计划、拟、建议 | 必须保留“拟”“计划”等语义 |
| 已批准事项 | 有真实审批记录 | 才能写“经批准” |
| 未知 / 冲突 | 缺失或相互矛盾 | 以【待补】占位，或先人工裁定 |

## 执行要点
- 表格数据按单元格取值（如 `经费测算!B5`），合计、比例本地复算，算术正确但口径或时点不同也要报告；
- 模型可协助抽取叙述性陈述，但 statement 必须是材料原文的连续片段，否则丢弃；
- 范文、案例库中的事实一律不得进入账本；
- 同一事项多份文稿共享事项级账本，事实变更时定位所有受影响的句子、表格与附件。

## 必须由人完成
- “发现冲突”节点：确认采信哪一项，或暂不采信（以待补占位）；
- 提纲确认时把已核实的关键数据列入 `confirm_facts`，或用 `add_facts` 补充人工事实；
- 关键事实变更：`gongwen task revise <任务> --fact F-003=40 --reason 核减`（联动正文、合计与附件）。

## 如何查看
MCP `evidence_lookup`（某句的来源、原文、公式、状态）；命令行 `gongwen task evidence <任务> <句号>`。
