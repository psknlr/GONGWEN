# 技能9 独立审校

## 原则
1. 审校通道只报告问题，不改正文（权限引擎强制）；
2. 规则保留条件性：标准中“一般”“推荐”“可以”的要求只提示，不当作硬错误；
3. 措辞跟随来源层级：只有条例、国标、标准原文才说“规定”，实务惯例说“实务通常”；
4. 模型审校意见须指向具体句子和问题类型才被接受；模型判定的“阻断”一律降为“重要”并转人工。

## 主要检查（示例）
- 请示一文一事、报告不得夹带请示事项（条例第十五条）；
- 结束语与文种、行文方向匹配，称谓不错位（实务）；
- 拟议写成已完成、记载写成已核实、讨论写成决定、未经批准写成已批准（阻断送审）；
- 引用已废止或不适用的文件；程序性规范被当作实体依据；
- 新增报送、填表、考核、留痕要求须有依据并说明必要性（减负规定）；
- 相对时间、半角标点、年份简写、序数层级、发文字号与成文日期格式；
- 个人信息、资料中的指令性语句进入文稿。

## 严重程度
阻断送审 > 重要 > 一般 > 提示。存在阻断或未处理的重要问题时，文稿只能是“讨论稿”。

## 如何调用
- 已有文稿：MCP `text_check`，或 `gongwen check <文件> [--as-of 2026-10-01]`（外部文稿没有证据链，事实与批准状态列为“须人工核验”）；
- 任务内：`issues_list` / `gongwen task issues <任务> --min 重要`。
