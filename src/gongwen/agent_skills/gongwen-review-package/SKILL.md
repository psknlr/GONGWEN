# 技能12 送审打包与留痕

## 交付件
| 文件 | 内容 |
|---|---|
| `*.docx` / `*.html` / `*.md` | 文稿（页眉标注状态与“须经人工审核”） |
| `workbench.html` | 审阅工作台：文稿、证据、问题、待确认、修改记录、版式，点击句子即可定位证据 |
| `review_package.json` | 结构化送审包（含内容哈希、规则库与版式配置版本） |
| `审阅说明.md` | 状态说明、事实依据表、问题、待确认事项、版本记录 |

## 文稿状态（只由规则判定，不由模型宣称）
- **讨论稿**：存在阻断或未处理的重要问题、内容性待补占位、未核实的关键数据、待核依据或待确认事项；
- **送审稿**：关键事实、依据和措施已完成相应核验，无阻断或重要问题；
- **经批准的待印发版本**：只有导入真实审批记录（签批人、时间、范围、来源）并与文稿内容哈希绑定后才可能出现；之后任何实质修改都会使审批失效。

## 必须由人完成
- “人工送审”节点：形成送审材料、退回修改或终止——任何参数都不能自动通过；
- 审批记录导入：`gongwen task approve <任务> --approver <姓名> --date <时间> --scope <范围> --source <OA流水号>`（须有权人员，系统不形成审批结论）。

## 系统不做的事
不自动签发、不加盖印章、不电子签章、不外发、不发布。

## 如何查看
`package_info`（MCP）、`gongwen serve`（本地审阅工作台，仅本机访问）。
