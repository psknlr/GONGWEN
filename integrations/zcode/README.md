# ZCode 对照与接入

## 从 ZCode 事件得到的教训
据公开报道，ZCode 的代码库索引（云端生成 Repo Wiki）曾触发本地工作区快照（含 `.git` 历史等）
由客户端直接上传至云存储、绕过服务端审计；后续版本删除了该功能并切断上传链路，随后开源。
对公文场景，这说明**“数据去哪儿”必须由唯一的、可审计的出口决定**，而不能依赖各功能自觉。本项目据此：

1. **出网网关是唯一出口**：模型调用、外部服务一律经 `EgressGateway`，默认拒绝，按环境路线、
   材料属性与模型获准级别判定，每次判定写审计日志（`harness/egress.py`）；
2. **准入先于模型**：材料先在本地扫描密级标志、个人信息、隐藏内容，再决定能否进入（`parsing/admission.py`）；
3. **最小化留痕**：审计日志只记哈希与摘要，不复制材料全文（`harness/session.py`）；
4. **没有任何“后台上传”功能**：仓库中不存在索引上传、遥测或快照同步代码。

## 宿主工具的文件访问不受本系统控制
无论 ZCode、Codex、Claude Code 还是 grok，宿主智能体通常可以直接读写工作区文件。
gongwen 的出网控制只覆盖经 gongwen 自身发出的内容。因此：
- 把 `[environment] data_dir` 设在宿主工具工作区**之外**（如 `~/.gongwen-data/<单位>`），
  MCP 服务用 `-C` 指向该目录；
- 不在宿主工具的“自动执行/yolo”模式下处理非公开材料；
- 宿主工具的代码索引、云端摘要等功能不得覆盖办文数据目录。

## 如何接入
ZCode 支持通过配置的命令、环境变量连接 MCP 服务。在其 MCP 设置中添加 stdio 服务：
命令 `gongwen`，参数 `-C <数据工作区> mcp`（具体界面与字段以 ZCode 当前版本为准）。
模型可在 gongwen 自己的配置中使用智谱 GLM（`[model] provider = "zhipu"`，密钥 `ZHIPUAI_API_KEY`），
并把 `open.bigmodel.cn` 加入 `[egress] allowed_hosts`。
